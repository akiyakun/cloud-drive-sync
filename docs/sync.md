# 同期の仕組み（sync.py）

Google Drive の資料を、AI が読みやすい形（Markdown と画像）にして `output/` へ同期する。Drive 側は読むだけで、変更しない。

## 使い方

```bash
python sync.py          # 新しいファイル・更新されたファイルだけを処理する
python sync.py --full   # 変更の有無にかかわらず全部作り直す
```

## 設定（config.local.toml）

| 項目 | 内容 |
|---|---|
| `token_file` | 読み取り専用の OAuth トークン（`auth.py` が作る） |
| `output_root` | 出力先。AI が読む場所。同期先ごとに `output_root/<name>/` |
| `state_root` | 前回の同期の記録の置き場所（既定は `state`）。AI が読む `output_root` とは分ける |
| `archive_root` | Drive から消えたファイルの出力の退避先（既定は `archive`）。AI が読む `output_root` の外に置く |
| `[[folders]]` | 同期するフォルダ（`name`、`folder_id`、`recursive`） |
| `[[files]]` | 個別に同期するファイル（`name`、`file_id`） |

書き方の見本は `config.example.toml`。`state/`・`archive/`・`output/` は git に入れない。

## 出力

| Drive 上の種類 | 出力 |
|---|---|
| Google ドキュメント | `<名前>.md`、`<名前>.images/`（画像・図形描画） |
| Google スプレッドシート | `<名前>.xlsx`、`<名前>.md`、`<名前>.images/` |
| Google スライド | `<名前>.pptx`、`<名前>.pdf`（Markdown 化は後回し） |
| それ以外 | 原本のまま |

Markdown を作れなかったときだけ、保険として `<名前>.pdf` を作る。変換の詳細は [export-format-findings.md](export-format-findings.md)。

## 変更されたファイルだけを取り直す

前回の同期の記録 `state/<同期先の名前>.json` に、ファイルごとに次を残す。

- Drive のファイル ID
- Drive 上の名前
- 出力先の中の場所
- 種類
- **Drive 上の最終更新日時**（`modifiedTime`）
- 作った出力の一覧

毎回、Drive のフォルダの一覧（ファイル 100 個につき 1 回の問い合わせ）だけを取り、記録と比べて次のように扱う。

| 状況 | 扱い |
|---|---|
| 記録に無い | **新規**: 書き出して変換する |
| 最終更新日時が変わった | **更新**: 書き出して変換し直す |
| 変わっていない | **変化なし**: 何もしない（書き出しの問い合わせもしない） |
| 名前が変わった | **移動**: 出力を新しい名前へ移したうえで作り直す（Markdown の中の画像リンク `<名前>.images/…` と見出しが変わるため） |
| 別のフォルダへ移った（名前は同じ） | **移動**: 出力を新しい場所へ移すだけ |
| Drive から消えた（削除・フォルダから外れた・共有が外れた） | **退避**: 出力を `archive/<同期先の名前>/<実行日時>/` へ移す（消さない） |
| 出力が手で消されていた | 作り直す |
| 変換処理の版が変わった | 全部作り直す |

### 安全策

- **一覧の取得が途中で失敗したときは、「Drive から消えた」とは判断しない。**通信エラーで出力を退避してしまう事故を防ぐ。
- 個別ファイル（`[[files]]`）は、Drive から「見つからない（404）」と返ってきたときだけ消えたと判断する。ほかのエラーでは判断しない。
- 書き出し・変換に失敗したファイルは、前回の出力と記録をそのまま残し、次回また試す。
- 前回は作ったが今回は作らなかった出力（例: 前回は保険の PDF だったが、今回は Markdown を作れた）は退避する。
- 移動先に別のファイルがあったときは、上書きせずに先にそれを退避する。
- 移動・退避で空になったフォルダは片付ける。
- 記録に載っていない出力（この仕組みを入れる前の出力など）があれば、件数と例を表示する。**自動では触らない。**

### 変換処理の版

`markitdown_ext/__init__.py` の `CONVERTER_VERSION`。**変換結果が変わる修正をしたら 1 つ上げる。**記録にある版と違えば、次の同期で全部作り直す（Drive 側が変わっていなくても、古い変換結果が残り続けないようにするため）。

### 検証

偽物の Drive（テスト用の代役）で、次の場面を再現して期待どおりに動くことを確かめた。

- 初回
- 2 回目（書き出し 0 回）
- 更新
- 名前変更（作り直して、画像リンクと見出しも新しい名前になる）
- 別フォルダへの移動（移すだけ）
- 一覧の取得失敗中の削除（判断しない）
- 一覧が取れたあとの削除（退避）
- 出力を手で消した
- 版の変更
- 保険の PDF とそこからの回復
- 記録にないファイル

## 今後の課題

| 課題 | メモ |
|---|---|
| archive の自動削除 | 設定で ON/OFF。例: archive の容量の上限（1GB など）を超えたら、古いものから自動で削除する |
| Drive の変更通知（changes API） | 今は毎回フォルダの一覧を取って比べている。資料が大量になったら、前回からの変更だけを教えてもらう changes API への切り替えを検討する |
| 定期的な自動実行・NAS への出力・Docker 化 | 引き継ぎ資料の⑥ |
