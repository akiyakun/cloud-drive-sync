# 同期の仕組み（sync.py）

Google Drive の資料を、AI が読みやすい形（Markdown と画像）にして `output/` へ同期する。Drive 側は読むだけで、変更しない。

## 使い方

```bash
python sync.py                        # 新しいファイル・更新されたファイルだけを処理する
python sync.py --full                 # 変更の有無にかかわらず全部作り直す
python sync.py --config 別の設定.toml  # 設定ファイルを指定する（既定は data/config.toml。環境変数 CDS_CONFIG でも変えられる）
python sync.py --archive-max-mb 1024  # 退避の合計が 1024 MB を超えたら、古い退避から削除する（管理画面で ON にすると付く）
```

## 置き場所

| NAS の中の場所 | Mac から | 中身 | AI が読む？ |
|---|---|---|---|
| `/volume3/dev/docker/cloud-drive-sync/` | `/Volumes/dev/docker/cloud-drive-sync/` | リポジトリ（プログラム）。`data/` に **Mac での開発用**の設定（`config.toml`）・記録（`dev/state/`）・退避（`dev/archive/`） | 読まない |
| `/volume3/app-data/cloud-drive-sync/` | `/Volumes/app-data/cloud-drive-sync/` | **本番（NAS のコンテナ）**の設定（`config.toml`）・記録（`state/`）・退避（`archive/`）。`app-data` はアプリが読み書きする共有フォルダ（ごみ箱なし） | 読まない |
| `/volume3/shared-data/CloudDrive/` | `/Volumes/shared-data/CloudDrive/` | **本番の出力**（例: `<プロジェクト名>/GoogleDrive-AI/`） | **読む** |
| `/volume3/.secrets/cloud-drive-sync/` | （見えない） | 本番の鍵 | 読ませない |

- 設定ファイルは、本番用（`app-data`）と開発用（リポジトリの `data/`）に分ける。同期先の顔ぶれが違ってよい（テストデータは開発用だけ、本番だけに足す資料もある）ため。
- `git` に入れないもの: `data/`、`.env`、`output/`（Mac での開発用の出力）。

### 秘密（鍵）の置き場所

**NAS の共有フォルダの中では `chmod`（ファイルごとの読み取り権限）が効かず、共有にアクセスできる人なら読めてしまう。**そのため、鍵は共有フォルダに置かない。
（逆に、共有フォルダの中は UGREEN 独自のアクセス権が優先される。「NAS の共有フォルダのアクセス権（UGREEN の ACL）」を参照）

| 使う場所 | 置き場所 | 中身 |
|---|---|---|
| NAS（コンテナ） | `/volume3/.secrets/cloud-drive-sync/`（共有フォルダの外で、SSH でしか入れない。持ち主はこのアプリ専用の NAS ユーザー `svc-cloud-drive-sync`） | `token.json` だけ（アプリの情報も含まれているので、同期にはこれだけで足りる） |
| Mac（開発） | `~/.config/cloud-drive-sync/`（環境変数 `CDS_SECRETS_DIR` で変えられる。本人だけが読める設定） | `credentials.json`（`auth.py` 用）、`token.json`、`token.dev.json`（テストデータ作成用） |

鍵を作り直したら（`python auth.py`）、NAS へは SSH で次のようにコピーする（持ち主は `svc-cloud-drive-sync`、本人だけが読める設定）。

```bash
sudo install -o svc-cloud-drive-sync -g users -m 600 <コピー元>/token.json /volume3/.secrets/cloud-drive-sync/token.json
```
- Mac から NAS の共有フォルダを見ると、濁点などが分かれた形（Unicode の NFD）のファイル名が返る。名前を比べる処理では NFC にそろえる。

## 設定（config.toml）

| 項目 | 内容 |
|---|---|
| `token_file` | 読み取り専用の OAuth トークン（`auth.py` が作る） |
| `output_root` | 出力先の土台。AI が読む場所 |
| `state_root` | 前回の同期の記録の置き場所（既定は `state`）。AI が読む `output_root` とは分ける |
| `archive_root` | Drive から消えたファイルの出力の退避先（既定は `archive`）。AI が読む `output_root` の外に置く |
| `[[folders]]` | 同期するフォルダ（`name`、`output`、`folder_id`、`recursive`、`ai_markdown`、`keep_originals`、`group`、`environments`） |
| `[[files]]` | 個別に同期するファイル（`name`、`output`、`file_id`、`ai_markdown`、`keep_originals`、`group`、`environments`） |

- `name` は同期先の名前。同期の記録（`state/<name>.json`）と退避（`archive/<name>/`）のフォルダ名にも使う。重複できない。
- `output` は出力先（`output_root` から見た場所）。省略すると `name` と同じ。
  - `{drive_name}` と書くと、Drive 上のフォルダ名（ファイル名）になる。例: `Example/GoogleDrive-AI/{drive_name}`
  - 出力先が変わったら（設定の変更や、Drive のフォルダ名の変更）、前回の出力先（記録の `out_dir`）から新しい出力先へ、出力を引っ越す。
- `environments` を書くと、その環境でだけ同期する。環境は環境変数 `CDS_ENV`（Mac での開発は `dev`（既定）、NAS のコンテナは `nas`）。テストデータの同期先は `["dev"]` にして、AI が読む NAS の出力先には出さない。
- 出力先の決まり（記録や退避が混ざらないように、同期を始める前に確かめる）:
  - **フォルダの同期先どうしは、同じ場所・入れ子にできない。**
  - **個別ファイルは、ほかの同期先と同じフォルダや、フォルダの同期先の外側（親）に置ける。**フォルダの同期先の中には置けない。個別ファイルは、置き場所のフォルダの中で自分の出力にしか触らない（記録にないファイルの検査や、空のフォルダの片付けをしない）。
- 場所の設定（`token_file`・`output_root`・`state_root`・`archive_root`）は、環境変数 `CDS_TOKEN_FILE`・`CDS_OUTPUT_ROOT`・`CDS_STATE_ROOT`・`CDS_ARCHIVE_ROOT` で上書きできる。`~` はホームフォルダになる。NAS のコンテナでは、同期先の一覧は同じ設定ファイルを使い、場所だけをコンテナの中の場所に上書きする。

書き方の見本は `config.example.toml`。本番の同期先は、管理画面の「同期先」からも編集できる（保存すると設定ファイルは作り直され、コメントは消える。[admin.md](admin.md) の「同期先の編集」）。

## 出力

同期先ごとに、出力のしかたを選ぶ（管理画面の「出力のしかた」。設定では `ai_markdown`・`keep_originals`）。

このツールの目的は 2 つある。

1. **AI が読む専用の同期**（`ai_markdown = true`。既定）: 資料を AI が読みやすい形（Markdown と画像）にする。人は読まない
2. **人が使う普通の同期**（`ai_markdown = false`）: Drive のファイルを NAS に置く。Google の公式アプリなどに Drive の権限を渡さずに済む

| Drive 上の種類 | AI 用に変換する | ＋元のファイルも残す（`keep_originals = true`） | 変換しない（人が使う） |
|---|---|---|---|
| Google ドキュメント | `<名前>.md`、`<名前>.images/`（画像・図形描画） | ＋`<名前>.docx` | `<名前>.url`（元のファイルを開くショートカット） |
| Google スプレッドシート | `<名前>.md`、`<名前>.images/` | ＋`<名前>.xlsx` | `<名前>.url` |
| Google スライド | `<名前>.pdf`（Markdown 化は後回し） | ＋`<名前>.pptx` | `<名前>.url` |
| そのほかの Google 形式（フォームなど） | 同期しない | 同期しない | `<名前>.url` |
| アップロードされた Excel（`.xlsx`・`.xlsm`） | `<名前>.xlsx.md`、`<名前>.xlsx.images/` | ＋原本 | 原本のまま |
| それ以外（PDF・画像など） | 原本のまま | 原本のまま | 原本のまま |

- 元のファイルを残すかは、AI 用に変換するときだけ選べる（既定は残さない。AI に読ませるだけなら要らないため）。
- ショートカット（`.url`）は Windows の「インターネット ショートカット」。Mac でも「Web サイトロケーション」として、ダブルクリックでブラウザが開く。Google 形式のファイルは、そのままではダウンロードできないため。
- 人が使う同期も、Drive → NAS の一方向。NAS 側で編集しても Drive には戻らず、Drive 側が更新されると上書きされる。
- Markdown を作れなかったときだけ、保険として `<名前>.pdf` を作る（アップロードされた Excel は、原本をそのまま残す）。実行結果には「Markdown を作れず代替」と出す。変換の詳細は [export-format-findings.md](export-format-findings.md)。
- **出力のしかたを変えた同期先は、次の同期で全部作り直す。**作らなくなった出力（例: 元のファイルを残さないにしたときの `.xlsx`）は退避へ移す。前回の出力のしかたは、同期の記録（`state/<名前>.json` の `options`）に残す。

## 変更されたファイルだけを取り直す

前回の同期の記録 `state/<同期先の名前>.json` に、ファイルごとに次を残す。

- Drive のファイル ID
- Drive 上の名前
- 出力先の中の場所
- 種類
- **Drive 上の最終更新日時**（`modifiedTime`）
- 作った出力の一覧

毎回、Drive のフォルダの一覧（ファイル 100 個につき 1 回の問い合わせ）だけを取り、記録と比べて次のように扱う。

| 状況 | 扱い |
|---|---|
| 記録に無い | **新規**: 書き出して変換する |
| 最終更新日時が変わった | **更新**: 書き出して変換し直す |
| 変わっていない | **変化なし**: 何もしない（書き出しの問い合わせもしない） |
| 名前が変わった | **移動**: 出力を新しい名前へ移したうえで作り直す（Markdown の中の画像リンク `<名前>.images/…` と見出しが変わるため） |
| 別のフォルダへ移った（名前は同じ） | **移動**: 出力を新しい場所へ移すだけ |
| Drive から消えた（削除・フォルダから外れた・共有が外れた） | **退避**: 出力を `archive/<同期先の名前>/<実行日時>/` へ移す（消さない） |
| 出力が手で消されていた | 作り直す |
| 変換処理の版が変わった | 全部作り直す |

### 安全策

- **一覧の取得が途中で失敗したときは、「Drive から消えた」とは判断しない。**通信エラーで出力を退避してしまう事故を防ぐ。
- 個別ファイル（`[[files]]`）は、Drive から「見つからない（404）」と返ってきたときだけ消えたと判断する。ほかのエラーでは判断しない。
- 書き出し・変換に失敗したファイルは、前回の出力と記録をそのまま残し、次回また試す。
- 前回は作ったが今回は作らなかった出力（例: 前回は保険の PDF だったが、今回は Markdown を作れた）は退避する。
- 移動先に別のファイルがあったときは、上書きせずに先にそれを退避する。
- 移動・退避で空になったフォルダは片付ける。
- 記録に載っていない出力（この仕組みを入れる前の出力など）があれば、件数と例を表示する。**自動では触らない。**

### 退避の自動削除

退避（`archive/`）は放っておくと増え続けるので、合計の上限を決めて古いものから削除できる。**既定は OFF**（管理画面の「退避の自動削除」で ON にする。上限の既定は 1 GB）。

- ON のとき、管理画面は `sync.py` に `--archive-max-mb <上限>` を付けて動かす。同期が終わったあとに、退避の合計を調べる。
- 上限を超えていたら、**実行日時のフォルダ（`archive/<同期先の名前>/<実行日時>/`）を 1 つの単位**として、同期先にかかわらず古い順に削除し、上限以下になったら止める。ごみ箱には入らず、元に戻せない。
- **今回の同期で退避したものは、上限を超えていても削除しない**（消えたことに気づく前に、元に戻せなくならないように）。
- 実行日時の形（`20261012-183600`）でないフォルダ・ファイル（手で置いたものなど）は削除しない（大きさには数える）。
- 削除で空になった同期先のフォルダは片付ける。
- 結果（退避の合計・削除した数と大きさ）は `--summary` の `archive` に書き出し、管理画面の「退避の自動削除」と「直近の記録」に出す。OFF のときも、退避の合計は調べて表示する。

### 変換処理の版

`markitdown_ext/__init__.py` の `CONVERTER_VERSION`。**変換結果が変わる修正をしたら 1 つ上げる。**記録にある版と違えば、次の同期で全部作り直す（Drive 側が変わっていなくても、古い変換結果が残り続けないようにするため）。

### 検証

偽物の Drive（テスト用の代役）で、次の場面を再現して期待どおりに動くことを確かめた。

- 初回
- 2 回目（書き出し 0 回）
- 更新
- 名前変更（作り直して、画像リンクと見出しも新しい名前になる）
- 別フォルダへの移動（移すだけ）
- 一覧の取得失敗中の削除（判断しない）
- 一覧が取れたあとの削除（退避）
- 出力を手で消した
- 版の変更
- 保険の PDF とそこからの回復
- 記録にないファイル

## Docker（NAS で動かす）

| ファイル | 内容 |
|---|---|
| `Dockerfile` | Python 3.12。実際に動かすユーザーは `docker-compose.yaml` で決める。コンテナの中の場所は環境変数で決める（`CDS_ENV=nas`、`/secrets/token.json`、`/data/config.toml`、`/output`、`/data/state`、`/data/archive`） |
| `docker-compose.yaml` | 安全設定（読み取り専用のコンテナ、権限を全部外す、など）は MCP のリポジトリと同じ。つなぐのは次の 3 か所だけ |
| `.env.example` | 動かすユーザーとつなぐ場所の見本。`.env` にコピーして使う（git に入れない） |

| コンテナの中 | つなぐ先（`.env`） | 扱い |
|---|---|---|
| `/secrets` | `CDS_SECRETS_DIR`（NAS: `/volume3/.secrets/cloud-drive-sync`） | 読み取り専用 |
| `/data` | `CDS_DATA_DIR`（NAS: `/volume3/app-data/cloud-drive-sync`） | 書き込み（本番の設定・記録・退避） |
| `/output` | `CDS_OUTPUT_DIR`（NAS: `/volume3/shared-data/CloudDrive`） | 書き込み（AI が読む出力） |

- コンテナは常に起動したまま（`restart: unless-stopped`）で、[管理画面](admin.md)と定期実行が動く。同期そのものは、管理画面が別のプロセス（`python sync.py`）で 1 つずつ動かす。
- 管理画面は `CDS_BIND_IP:CDS_PORT`（NAS の LAN の IP アドレス、既定のポート 8103）だけで待ち受ける。受け付けるホスト名は `CDS_ALLOWED_HOSTS`。
- コンテナは、このアプリ専用の NAS ユーザー `svc-cloud-drive-sync`（`CDS_UID`）・グループ `users`（`CDS_GID`）で動き、ファイルを**グループのメンバーも書き換えられる設定**で作る（`CDS_UMASK=0002`）。NAS のアカウントがそのグループに入っていれば、コンテナが作った出力・退避・設定を、SMB からも整理・編集できる。

### NAS の共有フォルダのアクセス権（UGREEN の ACL）

- UGREEN の共有フォルダには、ふだん見える権限（`ls` の `drwxrwxrwx` や `getfacl`）とは別に、**UGREEN 独自のアクセス権**（拡張属性 `system.ugacl_self`。`ls` の表示の最後の `+` が印）が付いていて、こちらが優先される。
- そのため、**UGOS に登録されていない UID（例: 最初に試した 28103）は、`drwxrwxrwx` と表示されていても読み書きできない**（`PermissionError`）。
- コンテナは、UGOS で作ったアプリ専用のユーザー（`svc-cloud-drive-sync`）で動かし、UGOS の画面で、使う共有フォルダ（`app-data`・`shared-data`）だけに読み書きを許可する。**`dev` 共有には許可しない**（ほかのリポジトリの `.env` などが読めてしまうため）。
- UGOS の画面ではユーザーやグループの番号が見えないので、SSH で `id <ユーザー名>` を実行して調べる。
- アプリごとにユーザーを分ける（`svc-docker` のような共通のユーザーにしない）。共通にすると、どのアプリのコンテナからも、ほかのアプリの鍵が読めてしまう。
- Mac では OrbStack で build と動作を確かめる（Mac は arm64、NAS は x86_64 なので、本番のイメージは NAS で build する）。Mac で試すときは、`.env` の代わりに Mac の場所を書いた設定ファイルを `--env-file` で渡し、記録と出力は開発用・本番用と別の場所にする。
- コンテナ（Python 3.12）と Mac（Python 3.13）の出力を比べ、Markdown の内容が同じことを確かめた。違いは画像のファイル名の番号だけで、これは Google が書き出すたびに番号を振り直すため（同じ位置の画像は中身も同じ）。

## 認証（OAuth）

- 同期は `auth.py` で作る `token.json`（読み取り専用の `drive.readonly`）を使う。`token.json` は「Drive 全体を読める鍵」なので、AI が読む場所・NAS の共有フォルダ・git には置かない（置き場所は「秘密（鍵）の置き場所」）。
- Google Cloud の OAuth 同意画面は、対象ユーザー「外部」・公開ステータス「**本番環境**」（2026-10-12 に「テスト中」から切り替え）。
  - 「テスト中」のままだと、リフレッシュトークン（入館証を再発行するための鍵）が **7 日で切れ**、そのたびにブラウザでの認証が必要になる。NAS での自動実行に向かないため切り替えた。
  - 個人利用（100 人未満）なので、Google の審査は受けていない。認証のときに「確認されていないアプリ」の警告が出るのは正常。
  - 本番環境にするために、ホームページ（このリポジトリ）と [プライバシーポリシー](privacy-policy.md) の URL を登録した。ロゴは登録しない（登録すると審査が必要になる）。
- 本番環境でも、次のときは鍵が切れるので、`python auth.py` で認証し直す（Google の公式文書より）。
  - 6 か月使わなかった
  - Google アカウントの「サードパーティ製のアプリとサービス」でアクセスを取り消した
  - 同じアプリで 100 回以上認証し直した（古いものから無効になる）
- サービスアカウント（ロボット用のアカウント）は使わない。人から共有された資料を、ロボット用のアカウントへ共有し直せないことが多く、読めなくなるため。
- 開発用の `dev/auth_dev.py`（`drive.file`、`token.dev.json`）も同じ仕組み。
