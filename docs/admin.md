# 管理画面（cds_admin）

ブラウザから、同期の状態を見たり、同期のしかた・通知・パスワードを変えたりする画面。NAS のコンテナの中で、定期実行と一緒に動く。

- 開き方: `http://<NAS の IP アドレス>:8103/`（家の中の LAN だけ）
- 初期パスワード: `admin`（変更するまで、画面の上部に警告が出続ける）

## できること

| 欄 | 内容 |
|---|---|
| 状態 | いまの状態（同期中／待機中）、自動同期（有効／停止中と、同期のしかた）、次の予定、前回の同期の結果 |
| 今すぐ同期・自動同期を止める／再開 | どの同期のしかたを選んでいても使える。同期中は「今すぐ同期」を押せない（同時に 2 つは動かさない） |
| 同期のしかた | 「○分ごと」（10〜1440 分）か「毎日○時」（カンマで区切って複数、24 個まで）のどちらか 1 つ |
| 同期先 | 同期先（Drive のフォルダ・ファイル）の一覧・追加・編集・削除。下の「同期先の編集」を参照 |
| 直近の記録 | 直近 20 回の結果（開始・きっかけ・時間・結果・件数・失敗の理由）と、それぞれのログ |
| 退避の自動削除 | ON/OFF と、退避の合計の上限（GB。既定は OFF・1 GB）。前回の同期のときの退避の合計も出す。決まりは [sync.md](sync.md) の「退避の自動削除」 |
| 通知（Discord） | Webhook URL の保存（画面では伏せ字）・削除・テスト送信 |
| パスワードの変更 | 8 文字以上。初期パスワード（admin）は使えない。変更すると、ほかのブラウザのログインは切れる。「今のパスワード」のまちがいは、ログインのまちがいと同じく数える（ロックしたらログアウトする） |

同期のしかた・自動同期の停止は、すぐに次の予定に反映される。「○分ごと」の次の予定は、前回の同期の開始（手動も含む）から数える。「毎日○時」で、同期の最中に予定の時刻が来たら、その回は飛ばす（終わった直後にもう 1 回は走らせない）。

## 同期先の編集

本番の設定ファイル（`app-data/cloud-drive-sync/config.toml`）の `[[folders]]`・`[[files]]` を、画面から書き換える。

| 操作 | 内容 |
|---|---|
| 追加・編集 | 名前、Drive の URL か ID（ブラウザのアドレスをそのまま貼れる）、出力先、サブフォルダも同期するか（フォルダだけ）。種類（フォルダ／ファイル）は変えられない（削除して追加し直す） |
| 削除 | 確認の画面を出してから削除する。これまでの出力（記録にあるもの）は退避（`archive/<名前>/<実行日時>/`）へ移し、同期の記録を消す。記録にないファイル（手で置いたものなど）は移さない |

保存する前に確かめること（だめなら保存せず、理由を出す）:

- 名前: 1〜64 文字、ファイル名に使えない文字（`\ / : * ? " < > |`）や先頭の `.` を使わない。ほかの同期先と重ならない（大文字・小文字の違いも同じとみなす）
- Drive: そのフォルダ・ファイルを、今の鍵で読めるか（Drive に問い合わせる）。種類が合っているか
- 出力先: `..` などで出力の土台の外に出ない。同期先どうしの出力先が混ざらない（同期の前に確かめる決まりと同じ。`{drive_name}` は Drive に問い合わせた名前で確かめる）
- 同期中ではないか（同期中は、追加・編集・削除のどれもできない）

保存したときに起きること:

- **設定ファイルは作り直す。**コメントは残らない。直前の内容は `config.toml.bak` に残る。画面に出ない項目（`environments` など）はそのまま残る
- **名前を変えたら、同期の記録（`state/<名前>.json`）と退避（`archive/<名前>/`）の名前も変える。**新しい名前の記録がすでにあるとき（前に同じ名前の同期先があった跡）は、古い記録を引き継がないように、変えない
- 出力先の変更・Drive のフォルダの変更は、次の同期で反映される（出力の引っ越し・前のフォルダの出力の退避は `sync.py` が行う。[sync.md](sync.md) を参照）
- 画面の出力先は、NAS の中の場所で表示する（`docker-compose.yaml` が `CDS_OUTPUT_DIR` を `CDS_OUTPUT_LABEL` として渡す。表示だけに使う）

## 仕組み

| ファイル | 役割 |
|---|---|
| `server.py` | 起動の入口（uvicorn で 0.0.0.0:8000 を待ち受ける。コンテナの外へは `CDS_BIND_IP:CDS_PORT` で出す） |
| `cds_admin/app.py` | 画面とボタンの処理（Starlette）、ログイン・CSRF 対策・安全のためのヘッダー |
| `cds_admin/runner.py` | 同期を別のプロセス（`python sync.py --summary …`）で 1 つずつ動かし、結果とログを残す。通知の判断。定期実行。同期を始める前の失敗（ログが書けない・設定が読めないなど）も「停止」として記録・通知する |
| `cds_admin/schedule.py` | 次に同期する時刻の計算と、入力のチェック |
| `cds_admin/security.py` | パスワード（scrypt）、ログインの状態、ロック |
| `cds_admin/settings.py` | 管理画面の設定（`admin.json`）の保存 |
| `cds_admin/targets.py` | 同期先の編集（入力の確認・設定ファイルの書き出し・名前の変更と削除の後始末） |
| `cds_admin/notify.py` | Discord への通知 |

管理画面が保存するもの（本番は `app-data/cloud-drive-sync/`、Mac での開発は `CDS_ADMIN_DIR`）:

| ファイル | 中身 |
|---|---|
| `admin.json` | パスワードの**ハッシュ**（パスワードそのものは保存しない）、初期パスワードのままか、Webhook URL、同期のしかた、ロックの設定、退避の自動削除 |
| `runs.json` | 直近 50 回の同期の結果 |
| `logs/<実行の ID>.log` | 直近 50 回の同期のログ（資料の名前が入るので、管理画面からだけ見る） |

`sync.py --summary <ファイル>` は、同期先ごとの件数・失敗・同期が止まった理由（鍵が無効など）・退避の合計と削除した数を JSON で書き出す。退避の自動削除が ON なら、管理画面は `--archive-max-mb` も付ける。管理画面はこれを読んで、結果を「正常／一部失敗（失敗したファイル・PDF で代替・一覧の取得の失敗がある）／停止（同期が止まった）」に分ける。

## 通知

| いつ | 内容 |
|---|---|
| 同期の結果が「正常」から変わったとき・問題の種類が変わったとき | ⚠️ 問題の内容（最大 5 件）。同じ問題が続いても、毎回は送らない |
| 問題のある状態から「正常」に戻ったとき | ✅ 解消 |
| ログインのロック | 🔒 ロックしたこと |

送り先は Discord の Webhook の URL（`https://discord.com/api/webhooks/…` など）だけを受け付ける（ほかの場所へ送らせないため）。URL はログや画面にそのまま出さない。

## 安全のための決まり

- **ログイン**: パスワードは scrypt のハッシュで確かめる。まちがえると 1 秒待つ。**3 分以内に 3 回まちがえると 15 分ロック**し、ロック中は正しいパスワードでも入れない（回数・時間は `admin.json` の `lockout`）。パスワードの変更の「今のパスワード」のまちがいも同じく数える（ログインしたままの画面を使った総当たりを防ぐ）。ロックしたら通知する。ロックは誰に対しても共通（家の中の LAN だけで使う前提。LAN の中の誰かがわざとまちがえ続けると本人も入れなくなるが、そのたびに通知で気づける）。
- **ログインの状態**: サーバーのメモリにだけ持つ（コンテナを再起動するとログアウトする）。Cookie は `HttpOnly`・`SameSite=Strict`、12 時間で切れる。
- **CSRF 対策**: すべてのボタン・フォームに、ログインごとの合言葉を入れて確かめる。ログイン画面は Cookie と画面の合言葉を比べる（同じブラウザで 2 回開いても、合言葉は使い回す）。さらに `Origin` ヘッダーが自分自身かを確かめる。
- **ホスト名の制限**: `CDS_ALLOWED_HOSTS` に書いたホスト名でしか受け付けない（DNS リバインディング対策）。`*` は使わない。
- **安全のためのヘッダー**: Content-Security-Policy（外部の読み込み・埋め込み・よそへのフォーム送信を禁止）、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: same-origin`、`Cache-Control: no-store`。
  - **`Referrer-Policy` を `no-referrer` にしてはいけない。**ブラウザがフォーム送信の `Origin` を `null` にしてしまい、Origin の確認でログインもボタンも使えなくなる（テストでは気づかず、ブラウザで試して見つけた）。
- **通信は暗号化しない（HTTP）**: 家の中の LAN だけで使う前提。パスワードは LAN の中を暗号化されずに流れる。暗号化したくなったら、UGREEN のリバースプロキシなどで HTTPS にする。

## 試し方

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
```

テストは Google・Discord にはつながない（通知は偽物に、同期は `--summary` を書く小さなスクリプトに置き換える）。ログイン・ロック・CSRF・ホスト名の制限・パスワードの決まり・同期のしかた・通知の送り分け・手動の同期のあとに自動の同期が続けて走らないこと、などを確かめる。

Mac で画面を試すとき（設定や記録は一時フォルダに置く）:

```bash
CDS_ADMIN_DIR=/tmp/cds-admin CDS_ALLOWED_HOSTS=localhost,127.0.0.1 .venv/bin/python server.py --host 127.0.0.1 --port 8103
```
